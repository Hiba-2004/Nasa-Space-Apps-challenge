# Architecture

## System shape

ASTRAVITAL is a local modular monolith. A Next.js browser interface calls one versioned FastAPI application. FastAPI owns validation, orchestration, and SQLite access; it imports `analytics` and `health_assistant` as ordinary Python packages. Those packages never listen on ports and do not access the database directly.

```text
Next.js UI -> /api/v1 FastAPI -> SQLite
                         |----> analytics.analyze_health(...)
                         `----> health_assistant.generate_guidance(...)
```

All runtime features work offline after Python and npm dependencies have been installed. There is no required account, hosted model, telemetry endpoint, or cloud database. The SQLite file and secrets are ignored by Git.

## Canonical domain models

- **Astronaut:** unique UUID, display name, optional mission role, creation time.
- **HealthMeasurement:** UUID, astronaut UUID, observed value, explicit UCUM-style unit token, metric, source, and observation time.
- **CheckIn:** UUID, astronaut UUID, UTC time, nullable mood/fatigue values and notes. Null means not reported, never “normal.”
- **HealthAssessment:** immutable output containing findings, guidance actions, provenance, and disclaimer.
- **Alert:** a reviewable notification. The type is reserved, but no threshold rules exist in the starter.
- **GuidanceAction:** a transparent action with rationale, urgency, and evidence links.
- **MissionContext:** simulated mission day, communication delay, environment, and synthetic flag.

Identifiers are UUIDs. API timestamps are ISO-8601 with an explicit UTC offset (`Z` is preferred). Requests with naive or non-UTC measurement/check-in timestamps are rejected. MVP units are `bpm`, `h`, `Cel`, and `mmHg`. Blood pressure is represented as separate systolic and diastolic observations sharing a timestamp.

## Data and trust boundaries

Pydantic schemas are canonical application models. SQLAlchemy records are storage details. OpenAPI generated by FastAPI is the canonical external contract. Inputs are validated at the API boundary. Assessment output is structured and traceable; it must not imply diagnosis, clinical validation, or a NASA-endorsed threshold. Real crew data is outside MVP scope.

The starter creates missing tables at process startup for convenience and includes Alembic migrations for durable schema evolution. Before production-like use, add authentication, authorization, encryption/access controls, audit logs, retention policy, and reviewed evidence governance. The current service must be treated as trusted-local and synthetic-data-only.
